# 串口助手

Rust 编写的 Windows x64 串口和网络调试程序，支持串口、TCP 客户端、TCP 服务端、UDP。[下载 Windows x64 版](https://github.com/xupeihao/serial-assistant/releases/latest/download/serial-assistant-windows-x64.exe)，下载后双击 EXE 即可启动。

1. 接好设备，点击「刷新」，选择 `COM` 端口。
2. 按设备要求设置波特率、数据位、校验位、停止位和流控，再点击「打开串口」。默认值为 `115200 / 8N1 / 无流控`。
3. 在发送区输入内容，点击「发送」，或在输入框内按 `Ctrl+Enter`。

- `Alt+1` 打开「控制」，`Alt+2` 打开「N6 串口升级」。对应窗口已显示时再按会最小化，最小化或关闭后再按会恢复或打开。快捷键在主窗口和拓展窗口内均可使用，后续拓展按菜单顺序分配 `Alt+3` 至 `Alt+9`；菜单同时显示对应按键。
- 只有主窗口显示时，按 `Esc` 最小化主窗口。已关闭或最小化的拓展不影响该操作；拓展仍在显示时不最小化主窗口。下拉列表展开时，`Esc` 先收起列表；编辑指令及文件选择弹窗保留原来的取消操作。
- 在拓展窗口内按 `Esc` 关闭当前拓展，可用对应的 `Alt+数字` 再次打开，保留窗口里的内容和配置。N6 升级进行中关闭窗口仍沿用停止发送及等待安装完成的保护逻辑。

- 上方「收发记录」用 `收←◆` 标识接收，用 `发→◇` 标识发送。记录之间留一空行。「HEX 显示」同时切换收发内容的显示格式，记录支持复制、自动滚动和清空。
- 接收时按 `CRLF`、`LF` 或 `CR` 分行。没有换行的数据连续约 20 ms 无新字节时也会显示为一条记录。时间戳取该条记录首批字节的读取时间。
- 发送记录在串口驱动返回写入结果后显示。部分写入或失败时，记录会显示已确认写入的字节数和错误。
- 用收发记录上方的「字体」和字号下拉框调整显示。默认微软雅黑 12 pt，字号可选 9 到 24 pt。
- 上下拖动收发记录下方的分隔线，可以调整上方记录区和下方面板的高度。左右拖动串口设置和发送区之间的分隔线，可以调整两区的宽度。
- 关闭窗口时自动保存窗口大小、最大化状态、两条分隔线的位置、「时间戳」开关和收发记录的字体字号，下次启动时恢复。设置保存在 `%LOCALAPPDATA%\SerialAssistant\settings.txt`。
- 勾选「时间戳」后，记录会显示本机读取数据或返回写入结果的时间，例如 `[14:32:08.127]`。切换开关会按原时间重绘当前记录。时间戳不计入 RX/TX 字节数。
- 文本收发共用 UTF-8 或 GBK 编码。文本发送可以追加 CRLF、LF 或 CR。
- HEX 发送可输入 `A1 B2 0D 0A` 或 `A1B20D0A`，发送对应的原始字节。
- 关闭再打开串口会保留窗口里的收发记录，RX/TX 计数从零开始。「清空记录」可手动清除，记录达到容量上限时会裁剪最旧的数据。
- 「保存记录」把点击时接收区内保留的全部收发内容另存为 UTF-8 文本，沿用当前文本/HEX 和时间戳显示。收发历史共用 96 KiB 原始数据及 4096 条的上限，超限后从最早的记录开始裁剪，已裁剪的内容无法从当前窗口保存。
- 关闭「自动滚动」后，可以停在当前位置查看记录。重新勾选会立即跳到最新记录，之后继续跟随新数据。

## 网络通信

在左下角「连接设置 → 类型」中切换串口、TCP 客户端、TCP 服务端或 UDP。每次使用一个连接，切换前先关闭当前连接。网络与串口共用主窗口收发区、文本/HEX、编码、时间戳、保存记录，以及控制拓展的快捷指令和 RTC 电脑时间按钮。

| 类型 | 需要设置 | 操作 |
| --- | --- | --- |
| TCP 客户端 | 远端 IP、远端口 | 点击「连接网络」，连接已监听的设备或程序 |
| TCP 服务端 | 本地 IP、本地口 | 点击「开始监听」，等待设备连接后双向收发 |
| UDP | 远端 IP、远端口、本地 IP、本地口 | 点击「打开 UDP」，发送到指定远端，同时接收本地端口收到的报文 |

- 地址填写 IPv4 或 IPv6 数字地址。`127.0.0.1` 用于本机通信；`0.0.0.0` 用于监听本机所有 IPv4 网卡，其他设备连接时填写电脑实际的局域网 IP。IPv6 的所有网卡监听地址为 `::`。UDP 本地与远端须使用同一种 IP 地址族。
- 本地端口允许填 `0` 自动分配，实际端口显示在底部状态栏；远端端口范围为 1～65535。默认远端是 `127.0.0.1:9000`，默认本地监听 `0.0.0.0:9001`。跨电脑通信时，系统防火墙需要允许所用端口。
- TCP 服务端同时接入一个客户端，其他连接会被关闭；客户端断开后继续监听，可接受下一个连接。「停止监听」释放服务端口。
- TCP 接收沿用换行符及 20 ms 空闲分组。UDP 每个报文单独显示，不把不同报文合并；可接收任意来源发到本地端口的报文，发送目标始终使用设置中的远端地址。单次 UDP 发送最多 65507 字节，支持 IPv4 广播。
- 网络收发记录带对端地址，例如 `收←◆[192.168.1.100:9000] ...`。RX/TX 只统计数据字节。TCP 的「已写入」和 UDP 的发送成功表示本机网络栈接受数据，不代表对端业务已经处理。
- 正常关闭主窗口时保存连接类型、IP 和端口到 `%LOCALAPPDATA%\SerialAssistant\network.json`，下次启动恢复设置，但不会自动连接或监听。
- N6 串口升级只使用串口连接，网络模式下不能开始升级。

## 拓展控制

在字号右侧点击「拓展 ▾」，选择「控制」打开侧窗口。先在主窗口打开串口或网络连接，再点侧窗口「快捷发送」里的按钮。结果显示在主窗口的收发记录中。

1. 用顶部的配置下拉框选择要用的配置。在旁边名称栏输入新名称，可点「新建」或「重命名」。
2. 点右下角「＋ 新增指令」，在弹窗里填写按钮名称和文本或 HEX 内容后点「保存」。HEX 内容在输入或粘贴后会立即校验，有非法字符或未配对的半字节时无法保存。已有指令可以通过「编辑指令」修改或删除。文本使用主窗口的收发编码，可以为每条指令指定换行。
3. 指令多时，用「上一页」「下一页」切换快捷按钮。配置和指令会保存到 `%LOCALAPPDATA%\SerialAssistant\control.json`。
4. 「保存配置」会把所有配置再次写入本机，「导出配置」可将所有配置和已保存的指令另存为一份 JSON。
5. 在另一台电脑点「导入配置」并选择这份 JSON。导入会保留本机已有配置，同名但内容不同的配置会自动加「（导入）」后缀，内容相同的重复导入不会新增副本。

### RTC 电脑时间按钮

在「＋ 新增指令」里将「指令类型」选为「电脑时间」，按钮名称默认是「RTC对时」，也可以自行修改。「时间格式」目前提供 `RTCSET YYYY-MM-DD HH:mm:ss`，下面显示实时预览。默认追加 CRLF，可以按设备要求改为无换行、LF 或 CR。

保存后，点击对应快捷按钮即可通过主窗口当前连接发送电脑本地时间，例如 `RTCSET 2026-11-18 15:53:30`。日期和时间由通信线程在开始写入前生成，配置里保存的是时间格式；反复点击会重新取时，导出到另一台电脑也会使用那台电脑发送时的本地时间。实际写入内容显示在主窗口收发记录中。

## N6 串口升级

先在主窗口打开设备串口，再点击「拓展 ▾ → N6 串口升级」。升级窗口直接复用主窗口已打开的串口，无需关闭连接，也没有单独的端口选择和日志区。选择进入方式、升级目标和镜像后点击「开始升级」。

升级期间自动使用 `115200 / 8N1 / 无流控`，支持命令 `MCUUPDATE` 进入和手动复位或上电进入，支持仅 AppNS 和 AppS/AppNS 配套升级。升级协议独占当前连接，普通发送、快捷指令和关闭串口按钮暂停使用。结束、取消或协议报错后会恢复原串口参数和普通收发；设备拔出或参数恢复失败时会报告断开。

镜像使用当前 N6 工程生成的 `-trusted.bin`。升级前会检查 STM32 头、长度、AppS/AppNS 向量和校验和。传输使用 YMODEM，并处理板端恢复下载提示。恢复时需选择与中断前相同的镜像组合。

升级窗口保留进度和当前状态，详细阶段、板端日志和结果统一显示在主窗口收发记录中，以 `升级◆` 标识。升级日志不受 HEX 显示和收发编码影响，也可以通过「保存记录」导出；RX/TX 计数包含升级协议实际读写的字节数，在本次升级结束时汇总。

「停止」可取消发送；最后一个结束块开始发送后，需等待板端校验、安装和重启。收到安装确认后会继续检查 AppNS 启动和版本打印。此扩展的协议迁移自 N6 工程的 `tools/UartUpgrade`。

## 从源码构建

在 Windows x64 上使用 Rust 和对应的 Windows 链接工具链构建。资源编译需要 Windows SDK 的 `rc.exe`（MSVC）或 MinGW 的 `windres`（GNU）。

```powershell
cargo test --locked
cargo build --release --locked
```

可执行文件位于 `target\release\serial-assistant.exe`。如果 GNU 工具链在中文路径下报 `dlltool` 无法读取文件，可以把 `CARGO_TARGET_DIR` 指向纯英文路径后重新构建。
